## react-markdown

react-markdown renders markdown as React elements using remark as the markdown
parser and rehype as the HTML processor.

```tsx
import ReactMarkdown from 'react-markdown'

function Markdown({ content }: { content: string }) {
  return <ReactMarkdown>{content}</ReactMarkdown>
}
```

## Safe by default

No `dangerouslySetInnerHTML` — all output is React elements. HTML in markdown is
sanitized by rehype's default escape behavior unless `rehypePlugins` is configured
to allow raw HTML (e.g., `rehype-raw`).

## GFM support (remark-gfm)

```tsx
import remarkGfm from 'remark-gfm'

<ReactMarkdown remarkPlugins={[remarkGfm]}>
  {content}
</ReactMarkdown>
```

remark-gfm adds:
- Tables
- Strikethrough (`~~text~~`)
- Task lists (`- [x] done`)
- Autolinks (`https://...`)
- Footnotes

## Custom Components

Override rendered HTML elements via the `components` prop:

```tsx
<ReactMarkdown
  components={{
    code({ className, children }) {
      return <CodeBlock code={String(children)} language={className?.replace('language-', '')} />
    },
    h1({ children }) {
      return <h1 className="text-2xl font-bold my-4">{children}</h1>
    },
  }}
>
  {content}
</ReactMarkdown>
```

## Server-side compatible

react-markdown itself is SSR-compatible. However, the package uses ESM which may
require dynamic import in some Next.js configurations. The MarkdownRenderer template
uses `React.lazy`-style dynamic loading via `useEffect` + `setState` for safe
isomorphic rendering.

## Heading hierarchy

Rendered markdown must preserve heading hierarchy (h1–h6) for screen reader
navigation. react-markdown uses semantic HTML elements by default.
