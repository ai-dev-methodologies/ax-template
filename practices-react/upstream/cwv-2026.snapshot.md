# Core Web Vitals 2026 — Thresholds and Definitions

Source: https://web.dev/articles/vitals  
Version: Stable lifecycle phase · Last updated: 2024-10  
Fetched: 2026-05-17

## The Three Core Web Vitals

### LCP — Largest Contentful Paint (Loading Performance)

Measures how quickly the largest visible element renders.

| Rating | Threshold |
|--------|-----------|
| Good | ≤ 2.5 seconds |
| Needs Improvement | 2.5s – 4.0s |
| Poor | > 4.0 seconds |

> "LCP should occur within 2.5 seconds of when the page first starts loading."

### INP — Interaction to Next Paint (Interactivity)

Measures how quickly a page responds to user interactions. Replaced FID as the official interactivity metric.

| Rating | Threshold |
|--------|-----------|
| Good | ≤ 200 ms |
| Needs Improvement | 200ms – 500ms |
| Poor | > 500 ms |

> "Pages should have an INP of 200 milliseconds or less."

### CLS — Cumulative Layout Shift (Visual Stability)

Quantifies unexpected layout movements during page load.

| Rating | Threshold |
|--------|-----------|
| Good | ≤ 0.1 |
| Needs Improvement | 0.1 – 0.25 |
| Poor | > 0.25 |

> "Pages should maintain a CLS of 0.1 or less."

## Measurement Standard

All three metrics are evaluated at the **75th percentile of page loads**, segmented across mobile and desktop.

## Lifecycle Status

All three metrics are in the **Stable** phase as of 2024-10. Future changes announced with advance notice on an annual update schedule.

## Application to ax-template

`blueprints/<domain>-ui-manifest.yaml` enforces these CWV thresholds:

```yaml
cwv:
  lcp_ms: 2000    # ≤ 2500 required per WCAG/CWV
  inp_ms: 150     # ≤ 200 required
  cls: 0.05       # ≤ 0.1 required
```

`trio_integrity_guard.sh` validates these fields exist (schema presence check).
Values are verified in SP5+ via Playwright + Lighthouse integration in `/ax-verify-L4`.
