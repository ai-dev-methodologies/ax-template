#
# WHY THIS FILE EXISTS
# --------------------
# BACKLOG P2-40 corrected a FABRICATED evidence anchor in
# templates/L1/components/currency-input.tsx (it cited a Stripe section + quote that the
# committed snapshot never contained). The gate registered alongside that fix
# (`--include-templates`, no --strict-templates) was ADVISORY, so restoring the fabricated
# quote produced a WARN and exit 0 — the "fabricated template anchors are blocked" claim
# was unearned. This ledger is the earned, non-vacuous half: the anchors listed here are
# verified against the on-disk snapshot bodies on every run-all-guards run and BLOCK.
#
# WHY IT IS A LEDGER AND NOT THE WHOLE TREE
# -----------------------------------------
# The first live full templates sweep (2026-07-28) found ~105 pre-existing quote↔snapshot
# misalignments across templates/L1/components/** — overwhelmingly quotes verified against
# the LIVE vendor page while the committed snapshot is a partial digest of it. Those are a
# real, separate backlog item; flipping the whole sweep to fatal would freeze the gate on
# work that is out of scope here. So the full sweep stays ADVISORY (still registered, still
# printed) and this explicitly-listed subset is FATAL. Grow the list as anchors are
# verified; the list may not shrink (see min_entries below).
#
# FORMAT
# ------
#   <repo-relative path>::<upstream_id>
# Anchor-scoped, not file-scoped, on purpose: currency-formatter.tsx cites TWO upstream
# snapshots and only one of them is disk-clean (see the exclusion note below). Protecting
# the file wholesale would have forced a choice between an unearned pass and rewriting an
# unrelated quote purely to make a gate green. Listing the anchor is the honest unit.
#
# NON-VACUITY (enforced by the guard, exit 2 on each)
# ---------------------------------------------------
# missing file · zero entries · missing `min_entries` directive · fewer UNIQUE entries than
# min_entries · min_entries below the guard-pinned live floor · a duplicated identity · an
# unsafe/non-repo-relative path · a required identity absent · an entry whose file does
# not exist · an entry whose file carries no upstream_id evidence · an entry whose declared
# upstream_id is not actually cited by that file · a protected `quote`/`section` that is
# missing, not a string (int/null/list/dict — never coerced), blank, or (quote) shorter than
# the guard's substance floor · a protected anchor whose snapshot body is absent from disk ·
# zero anchors scanned.
#
# IDENTITY, NOT ROW COUNT
# -----------------------
# A count is not an identity. `min_entries: 2` was once satisfiable by DELETING the
# currency-input row and DUPLICATING the clean currency-formatter row: the guard then
# checked the formatter twice, exited 0, and currency-input — the anchor this whole gate
# exists for — became free to fabricate. So the ledger is now read as a SET: duplicates are
# rejected, min_entries counts unique identities, and each `# require:` directive below
# names an identity that MUST be present regardless of how many rows the file has. The same
# two identities are additionally pinned as LIVE_REQUIRED_PROTECTED_IDENTITIES inside
# evidence_quote_spotcheck_guard.sh, so dropping one takes two coordinated edits.
# require: templates/L1/components/currency-input.tsx::stripe-billing-2026-05
# require: templates/L1/components/currency-formatter.tsx::stripe-billing-2026-05
#
# min_entries — the protected set MAY NOT BE REDUCED below this count. The guard
# additionally pins LIVE_MIN_PROTECTED_ENTRIES=18 in evidence_quote_spotcheck_guard.sh for
# the real repo tree, so lowering the directive here does not silently shrink the gate.
