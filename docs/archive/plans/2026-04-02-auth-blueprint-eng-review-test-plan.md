## Affected Pages/Routes
- `/login` — 구글/카카오/이메일 로그인 시작과 실패 상태 확인
- `/signup` — 이메일 가입, 미인증 상태 생성, 재발송 흐름 검증
- `/verify-email` — 인증 링크 성공, 만료, 중복 클릭(idempotent) 처리 검증
- `/logout` — 세션 종료와 UI 상태 초기화 확인
- `/me` 또는 `/auth/me` — 최소 UI 상태 반환, roles 반영, 만료 세션 처리 검증
- 보호 라우트(예: `/dashboard`) — 미인증/권한 부족/정상 접근 흐름 검증
- 백엔드 auth API (`/auth/refresh`, provider callback, account-linking endpoint) — refresh, linking, fallback 경로 검증

## Key Interactions to Verify
- 구글 로그인 성공 후 보호 라우트 접근 가능
- 카카오 로그인 성공 후 roles 기반 UI 상태 반영
- 이메일 가입 후 미인증 상태 유지, 보호 기능 차단
- 인증 메일 재발송 후 최신 링크만 유효하게 동작
- 만료된 인증 링크 접근 시 명확한 안내 표시
- access token 만료 시 refresh 1회 시도 후 성공하면 요청 재개
- refresh 실패 시 명시 로그아웃과 재로그인 유도
- 동일 사용자가 다른 provider로 로그인 시 명시적 account linking 흐름 진입
- provider 장애 시 해당 provider 실패 표시 + 이메일 fallback 유지

## Edge Cases
- 동시 401 발생 시 refresh mutex/queue로 중복 refresh 방지
- refresh token rotation 경쟁 상태에서 grace window 처리
- 구글/카카오 provider 비활성화 flag 상태에서 로그인 버튼/엔드포인트 처리
- 권한 부족(member가 manager/admin 전용 화면 접근) 차단
- `/auth/me` 응답이 느리거나 실패할 때 최소 UI 복구
- CORS/CSRF 설정 오류 시 사용자에게 보이는 실패 상태
- verify 스크립트가 정상 코드 false-positive 없이 통과시키는지
- OpenAPI 계약 변경 시 프론트 생성 타입/클라이언트와 일치하는지

## Critical Paths
- 이메일 가입 → 미인증 상태 → 인증 메일 확인 → 로그인 → 보호 라우트 접근
- 구글 로그인 → `/auth/me` 조회 → 역할 기반 화면 표시
- 카카오 로그인 → account linking 필요 시 linking 완료 → 재로그인/접근 확인
- access token 만료 → refresh → 원래 요청 재개
- provider 장애 → fallback 경로로 이메일 로그인 유도
- PR/CI에서 보안/계약/RBAC 위반 verify 실패 → 자동 수정 루프 또는 HITL 전환
